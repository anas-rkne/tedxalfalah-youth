# 18 — خطة اختبار شاملة لنظام جدار الأسئلة الحية (Live Q&A Wall)

> خطة اختبار تفصيلية تغطي **كل** نقطة نهاية، و**كل** سيناريو happy-path و edge-case و failure،
> على 5 مستويات: منطقي (L0) ← وحدات (L1) ← تكامل API (L2) ← متصفح حقيقي (L3) ← إنتاج وحِمل (L4).
>
> **الحالة**: وُضعت هذه الخطة بعد جولة تحليل كاملة للكود (2026-09-25). كل بند يحمل رقمه
> ونوع الفحص والنتيجة المتوقعة. أي بند بلا تغطية آلية يُعتبر فجوة.

---

## 0. كيف تُشغَّل الاختبارات

```bash
# 0) أوامر npm الجاهزة (نفس الترتيب)
npm run test:i18n        # L0 — تطابق مفاتيح ar/en
npm run test:qa:unit     # L1 — وحدات بلا خادم
npm run typecheck        # tsc --noEmit
npm run test:qa:api      # L2 — تكامل عبر HTTP
npm run test:qa:cluster  # L4 — عمليتان إضافيتان + قفل التخزين
npm run test:qa:e2e      # L3 — متصفح حقيقي
npm run verify:qa        # كل ما سبق بالترتيب

# أو يدوياً:

# 1) تشغيل خادم معزول (لا يمسّ store/ الحقيقية)
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/qa-test-server.ps1 -Port 3110

# 2) فحوص منطقية سريعة (L2) — تغطي كل نقاط النهاية
node scripts/qa-suite.mjs --base=http://localhost:3110

# 3) فحوص storage والوحدات (L1) — بلا خادم
node scripts/qa-unit.mjs

# 4) فحص مفاتيح الترجمة (L0)
node scripts/i18n-keys.mjs

# 5) التزامن عبر عمليتين (L4) — يشغّل عمليتي next start 3111/3112
node scripts/qa-cluster-test.mjs --base=http://localhost:3110

# 6) متصفح حقيقي (L3) — المتصفح الآلي لا يولّد رمز Turnstile، لذا يستخدم
#    خادم التطوير المعزول (playwright.qa.config.ts)
npx playwright test --config=playwright.qa.config.ts
```

| المتغيّر | الأثر |
| --- | --- |
| `QA_DATA_DIR` | مسار بيانات معزول. **يجب** أن يوجّه `qa-data.json` و`qa-votes.json` و`qa-surveys.json` جميعها. |
| `TURNSTILE_SECRET_KEY` | عند الغياب و`NODE_ENV` لا يساوي production يمرّ الفحص (fail-open) — يُستخدم في الاختبار. |
| `UPSTASH_REDIS_REST_*` | عند الغياب و`NODE_ENV` لا يساوي production يمرّ الفحص بلا تحديد معدّل — يُستخدم في الاختبار. |
| `ALLOWED_API_ORIGINS` | يجب أن يحوي `http://localhost:<port>` وإلا رُفض كل طلب يحمل `Origin`. |

### حدٌّ معرَّف بصراحة

القفل ملفّي، يحمي عمليتَي Node على **نفس المضيف ونظام الملفات**. تشغيل ثلاث نسخ `pm2` على أجهزة/تخزين مختلف لا يحميه. الحل الحقيقي هناك: تخزين مشترك أو قفل موزّع — خارج نطاق هذا الإصلاح.

وكذلك ما يلي **غير مُثبت** ولا ينبغي قراءته كأنه مُثبت:

1. **مسار الإنتاج لـTurnstile لم يُختبر على Cloudflare حقيقي**، ولا Upstash. الاختبارات تستخدم بديلاً يصدِر رمزاً فوراً، وتتحقق من أن الواجهة تنتظر الرمز وترسله — لا من أن Cloudflare يقبله.
2. **فحص الأدوار السلوكي (`viewer`) متخطّى** لعدم وجود `JWT_SECRET` في بيئة الاختبار، والدور في `ensureViewerToken` قد يُعاد من Users store، فالتوقيع المزيّف ليس دليلاً كافياً.
3. **قراءة المستخدمين ما زالت تعتمد Google Sheets**، فالعطل و`quota exceeded` خطران زمنيان حقيقيان. الكاش (15 دقيقة stale + in-flight dedupe) يقلّل الاستهلاك ولا يزيل التبعية.
4. **`?session=` في رمز QR عاد له معنى** (كان محذوفاً في جولة سابقة): صار يُقرأ في `LiveParticipate`، و`?session=` لجلسة منتهية يعرض رسالة صريحة بدل دخول صامت إلى جلسة أخرى. البند 348 و350.
5. **الأسئلة على الشاشة تُدار من الخادم فقط**، و`resolveScreen` طبقة صمود ثانية: لو تسرّب مؤشر لسؤال غير مؤهَّل (بيانات قديمة أو مسار تجاوز الحارس) فالمشاهِد يرى `hold` لا سؤالاً غير مقصود.
6. **حدّ الإجابات 5 طلبات/10 دقائق لكل IP** مشترك بين كل الحاضرين على نفس الشبكة. خلف شبكات مؤسسية كبيرة قد يظهر هذا الحد sooner من المتوقّع؛ القابل للضبط بعد قياس حقيقي.
7. **بقية الموقع خارج Q&A لم تُدقّق** (الفورمات، الخرائط، PWA، SEO، a11y).
