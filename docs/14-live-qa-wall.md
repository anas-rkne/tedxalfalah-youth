# 14 — نظام جدار الأسئلة الحية (Live Q&A Wall)

نظام تفاعلي يتيح للجمهور المشاركة عبر هواتفهم أثناء الفعالية: إرسال أسئلة مفتوحة،
والتصويت على استفتاءات اختيارية، مع شاشة عرض كبيرة ولوحة تحكم للمشرف.

## الفكرة العامة

- **الجمهور** يفتح صفحة `/{locale}/live` على هواتفهم ويسجّل حضوراً خفيفاً (اسم أو رمز).
- **المشرف** يستقبل الأسئلة في لوحة `/{locale}/admin/live` ويوافق/يفلتر قبل عرضها.
- **شاشة العرض** (`/{locale}/live/screen`) تُفتح على الشاشة الكبيرة وتدور الأسئلة المعتمدة
  وتُظهر نتائج الاستفتاءات لحظياً.
- **شاشة المتحدث** (`/{locale}/live/speaker`) تُعرض خلف المتحدث/على شاشتك المساعدة وتُظهر
  سؤالاً واحداً بارزاً (المميّز أو الأعلى تصويتاً) مع زر «تمت الإجابة»، وتفاعل مباشر مع الجمهور.
  يمكن للمشرف تعطيلها/تفعيلها لكل جلسة من اللوحة.
- **الاستفتاء** اختياري: عدد خيارات 2–6، يمنع التصويت المزدوج من نفس الحضور.
- **المزامنة** عبر استطلاع دوري (polling) كل 3–5 ثوانٍ — لا WebSocket، متوافق تماماً مع VPS/PM2.

## تخزين البيانات

بيانات الجلسات والأسئلة والاستفتاءات تُحفظ في ملفات JSON **على السيرفر** خارج مجلد البناء:

- `qa-data.json` — الجلسات/الأسئلة/الاستفتاءات/الحاضرون + إحصائيات.
- `qa-votes.json` — سجل الأصوات (ملف منفصل لتقليل حجم الملف الرئيسي والتسهيل على منع التكرار).

المسار: يُضبط عبر متغير `QA_DATA_DIR` (مسار مطلق ثابت، مثلاً
`/home/tedx/htdocs/tedxalfalahyouth.com/store`). إن لم يُضبط، يعتمد على `process.cwd()/store`.

كل عملية كتابة تمر عبر **قفل كتابة** (write lock) في العملية الواحدة، والكتابة **ذرّية**
(الكتابة لملف مؤقت ثم rename) لتفادي تلف الملف عند تزامن عدة أجهزة.

> `store/` مُضاف إلى `.gitignore` — لا يُرفع للـ git لأنه يحتوي بيانات فورية.

## متغيرات البيئة

| المتغير | الوصف |
| --- | --- |
| `QA_DATA_DIR` | المسار المطلق لملفات بيانات Q&A (اختياري، يُفضَّل في الإنتاج) |
| `NEXT_PUBLIC_TURNSTILE_SITE_KEY` | مفتاح Turnstile العام (لحماية الجمهور) — نفس متغير بقية الفورم |
| `TURNSTILE_SECRET_KEY` | مفتاح Turnstile السري |
| `ADMIN_PASSWORD` | كلمة مرور لوحة الإدارة (لتوليد JWT) — نفس متغير لوحة الطلبات |

Turnstile: عند غياب المفتاح (بيئة تطوير) لا يُعرض الودجت ولا يُرفض الإرسال من العميل،
ودالة الخادم تعتبر التحقق ناجحاً — نفس سلوك بقية فورم الموقع.

## سير العمل (للمشرف يوم الفعالية)

1. افتح لوحة الإدارة `/en/admin/live` (نفس جلسة تسجيل الدخول للوحة الطلبات).
2. **إنشاء جلسة** بعنوان (مثلاً "Q&A Session 1") ثم **تفعيل** — هذا يفتح استقبال الأسئلة.
3. ضع شاشة العرض `/en/live/screen` على الشاشة الكبيرة (المتصفح في وضع ملء الشاشة)،
   وشاشة المتحدث `/en/live/speaker` على شاشة المتحدث إن وُجدت.
4. أعلن للجمهور لفتح `tedxalfalahyouth.com/en/live` على هواتفهم.
5. في اللوحة: **موافقة/رفض** الأسئلة الواردة، ويمكن **تمييز** سؤال ليتصدر.
6. التحكم المنفصل بالعرض لكل سؤال (3 أزرار بجانب كل سؤال):
   - **يظهر للمتحدث / مخفي عن المتحدث** — يخص شاشة `speaker` فقط.
   - **يظهر على الشاشة / مخفي من الشاشة** — يخص شاشة `screen` الرئيسية فقط.
   - **تعطيل/تفعيل شاشة المتحدث** (بجانب إحصائيات الحضور) — يوقف شاشة المتحدث بالكامل
     للجلسة الحالية (تعرض «الشاشة معطّلة») دون التأثير على الشاشة الرئيسية.
7. للاستفتاء: أنشئ استفتاءً (سؤال + 2–6 خيارات)، ثم **بدء**، وعند الانتهاء **إيقاف** ثم
   **عرض النتائج** لتظهر على الشاشة.
8. عند الانتقال للجلسة التالية: أنشئ جلسة جديدة وفعّلها (تعطّل السابقة تلقائياً).

## التحكم بالعرض (منفصل: متحدث / شاشة)

لكل سؤال حقلان مستقلان في البيانات (`QaQuestion`):
- `showOnSpeaker?` — يظهر على شاشة المتحدث (`/live/speaker`).
- `showOnLive?` — يظهر على شاشة العرض الرئيسية (`/live/screen`).

ولكل جلسة حقل `speakerEnabled?` (تفعيل/تعطيل شاشة المتحدث كلها).

- `normalizeData` يملأ القيم الناقصة بالمقدار `true` → توافق تام مع بيانات JSON القديمة.
- نقطة قراءة الجمهور `GET /api/qa/session/current` تأخذ `?view=live|speaker` (الافتراضي `live`):
  - `live` → يرجع الأسئلة حيث `showOnLive !== false`.
  - `speaker` → يرجع الأسئلة حيث `showOnSpeaker !== false`.
  - يرجع أيضاً `speakerEnabled` للجلسة و`answered` لكل سؤال (يستخدم للتمييز في شاشة المتحدث).
- الإجراءات الجديدة في `POST /api/qa/admin/moderate`:
  - `setVisibility { questionId, showOnSpeaker?, showOnLive? }` — تحديث عرض سؤال.
  - `setSpeaker { enabled }` — تفعيل/تعطيل شاشة المتحدث للجلسة.

## وضع ملء الشاشة (Full Screen)

شاشتا العرض تُفتح في ملء الشاشة **بدون الهيدر/الفوتر/شريط المتصفح**:
- الـ `middleware.ts` يضيف ترويسة `x-stage-mode` للمسارات `/live/screen` و`/live/speaker`.
- `layout.tsx` يكتشفها فيخفي `Header` و`FooterContent` و`ReadingProgress` والتحليلات و`PageTransition`.
- المكوّنات نفسها (`LiveScreen`/`SpeakerView`) ملء الشاشة أصلاً (`min-h-screen bg-zinc-950`).
- افتح الصفحة ثم اضغط F11 (أو زر ملء الشاشة في المتصفح) لعرض بلا حواف نهائياً.

## الحماية

- كل نقاط `api/qa/admin` تتطلب JWT مشرفاً (`Authorization: Bearer`) + دور `admin` + rate limit للمشرف.
- نقاط الجمهور العامة محمية بـ rate limit + Turnstile + التحقق من الأصل (Origin) + تعقيم النص (escapeHtml).
- التصويت يمنع التكرار من نفس `attendeeId`، والاستفتاء المغلق يرفض الأصوات.
- التخزين الملفي يفرض خلطاً في اسم دليل الإنتاج؛ يُنصح بإبقاء `QA_DATA_DIR` خارج `public`.

## البناء والرفع (الإنتاج)

نفس إجراء بقية الموقع (`output: "standalone"` + pm2):

```
npm run build                        # يشمل postbuild لنسخ public/ و static/
cp .env.local .next/standalone/.env.local
# أعد تشغيل العملية في pm2 (tedxalfalahyouth)
```

ضع `QA_DATA_DIR` في `.env.local` بنسخة الإنتاج على مسار ثابت بين عمليات البناء.

## ملاحظات

- صفحة الجمهور والشاشة تُعاد معا فقط عند الحاجة (dynamic) للحفاظ على حداثة البيانات.

- الواجهة ثنائية اللغة عبر `next-intl` (`messages/en.json` / `messages/ar.json`).
